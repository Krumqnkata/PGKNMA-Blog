# Игри

`/games` е каталогът, `/games/:slug` е игровият екран. Шестте стойности на
slug са `quiz`, `word`, `code`, `robot`, `memory`, `hunt`.

React показва само видимото състояние от Django. Не пази отговори, скрити
карти или алгоритъм за начисляване на точки. API типовете и функциите са
в `src/lib/games-api.ts`; контролите — в `src/components/games/GameBoard.tsx`.
Страницата се зарежда отделно и няма нови runtime зависимости.

URL параметърът `session` позволява презареждане и възстановяване. Той
не дава достъп до чужда игра: API проверява собственика. Начало без този
параметър също възстановява активната игра за избрания режим. Ключовете
в React Query включват потребителя. Навигация или смяна на профил
прекратява прилагането на закъснели отговори към стария екран.

При мрежова грешка „Повтори действието“ изпраща същия UUID и същото тяло.
При 409 се изтегля състоянието от сървъра. Бутоните се блокират докато
има заявка. Успехът обновява каталога и съществуващия прогрес/класация.
Гостите могат да разглеждат правилата, а за игра отварят текущия login dialog.

Роботът се подрежда с бутони нагоре/надолу. Всички игри работят с
клавиатура и докосване. Няма бонуси за бързина, задължително влачене или
автоматично затваряне на картите след кратък таймер.

## Проверки

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test -- src/components/games/GameBoard.spec.tsx
npx.cmd playwright test tests/e2e/games.spec.ts --workers=2
npm.cmd run build
```

Playwright проверява шестте игри на desktop/mobile, възстановяване след
reload, login и повторена заявка при загубен отговор. Използва API mocks;
истинските правила и награди се проверяват в backend `blog.test_games`.

Backend подготовката, съдържанието и API договорът са описани в
`backend backup 27.07.2026/cms/docs/GAMES.md`. За включване са необходими
миграцията и `prepare_games --start-date YYYY-MM-DD --activate`.
